## 1. Registered Tauri command and data-flow inventory

| Registered command | Current SQLite behavior | Unresolved authority / integrity boundary |
| --- | --- | --- |
| `create_firm_library_item` | Tauri validates optional service ID **shape**, and persistence enforces one of 8 named categories, nonempty name ≤200 characters with searchable normalized name, description ≤2000 characters, at most 262144 input bytes and JSON **object** root. `normalize_firm_library_definition` parses JSON, serializes a canonicalized object and records its SHA-256. A SQLite `IMMEDIATE` transaction checks a supplied service type is live, inserts the library item, immutable v1 row and `FIRM_LIBRARY_ITEM_CREATED` audit together | The handler does not receive independently verified publisher, firm administrator or native grant. Global (`service_type_id = NULL`) and service-scoped versions are accepted; source metadata/audit do not establish professional approval |
| `publish_firm_library_version` | Handler checks library item UUID shape. Persistence canonicalizes JSON, requires nonarchived item, opens `IMMEDIATE`, allocates `MAX(version_number)+1`, inserts a new immutable version and `FIRM_LIBRARY_VERSION_PUBLISHED` audit atomically; historic versions remain unchanged | No verified publisher, firm service-scope write grant, expected-latest version CAS, semantic professional approval or prohibition against publishing identical canonical payload as another version. DB locking serializes writers but does not authorize them |
| `list_firm_library_versions` and `list_firm_library_items` | Read historical canonical payload/hash and latest item/version metadata, optionally filter item category/service; version listing checks nonarchived item | Read/export grants and historical compatibility unresolved. Do not destroy old versions or mislabel hash as independently certified evidence |
| `create_statutory_compliance_requirement` | Registered downstream mutator: takes *explicit* `engagement_id` and `firm_library_version_id`, requires live engagement, live library item in `STATUTORY_COMPLIANCE_REQUIREMENT` category, optional service-type match and a **32-byte stored hash**. Within `IMMEDIATE`, rejects duplicate library item in same engagement, snapshots exact item/version/hash into immutable requirement row, creates `UNDETERMINED/UNASSESSED` initial assessment and `STATUTORY_COMPLIANCE_REQUIREMENT_ADDED` audit | No independently authenticated permission to attach methodology to an engagement. **Critical distinction:** it validates the hash *length* but does not recompute `SHA-256(definition_json)` before consuming a stored version. Native library publishing computes the digest correctly, so a mismatch would require corrupted/synthetically inserted SQLite data or another proven ingest path; this test does NOT demonstrate such a Tauri injection route |

**Downstream distinction:** The inspected `create_engagement_from_template` route consumes `engagement_template_versions` instead, not `firm_library_versions`. Firm-library content has an **actual** downstream statutory-compliance consumer; it is incorrect to say the library is only presentation text or to assume all firm-library categories are automatically wired into engagement template instantiation. The installed React library editor currently sends `definitionJson: JSON.stringify({content})` but native code accepts any valid JSON object under the byte cap. The React UI is not an IPC authorization barrier.

## 2. Actual migration integrity and provenance

Migration `0011_firm_library.sql` has an active-item unique index on category, service scope and normalized name, `UNIQUE(item_id, version_number)`, and `BEFORE UPDATE/DELETE` abort triggers preserving all old firm-library version rows. Migration `0019_statutory_compliance.sql` maintains exact version foreign keys and `BEFORE UPDATE/DELETE` abort triggers for requirement and assessment records. **These are local SQLite integrity protections**, not independent authentication of users, issuer/grants, migration custody, off-device attack immunity or professional approvals.

New [test-only Rust suite](../../src-tauri/src/workpaper_firm_library_native_tests.rs) uses **production migrations** with disposable SQLite. It characterizes:

1. Exact canonical JSON + SHA-256, matched `FIRM_LIBRARY_ITEM_CREATED` audit, and refusal to UPDATE/DELETE a version.
2. Invalid service, JSON root and category refusal; rejection of publication to archived item; no additional item/version/requirement/assessment/audit counts on denial.
3. Same-payload new version under the legacy publication command, preserving the old immutable version/hash and recording new audit (NOT a trusted publisher or an approved compare-and-swap).
4. Statutory downstream reject on wrong library category and service scope, duplicate item refusal, exact version pinning and nonretroactive historical hash/text after a later publication.
5. Explicit **fixture-only**, newly inserted mismatched 32-byte hash/version: current statutory consumer accepts the claimed stored hash without digest recomputation. Historic original version is untouched; this requires direct synthetic database insertion, not available as an existing registered Tauri publish payload. It proves a **downstream trust assumption**, not exploitability in the installed webview threat model.

The [Node source tripwire](../../tests/workpaper-firm-library-boundary.test.mjs) detects source drift around handler registration, current locking/audit and consumer checks, and keeps all new Rust tests behind `#[cfg(test)]`. **Neither suite runs authenticated denial against a registered Tauri handler**.

## 3. Deferred security acceptance — NOT IMPLEMENTED / NOT RUN

- Missing/foreign/expired/revoked **verified native publisher**, and service-wide vs firm-wide publishing policy; independent issuance and revocation under the actual writer lock.
- Caller-submitted JSON object contents, semantic validation by selected category, stale concurrent publisher/CAS policy, changed category/service scope and permitted duplicate content.
- Statutory consumption: verified engagement-scoped attachment grant, foreign client/service/version, archive/revocation races, duplicate/semantic conflicts, missing or mismatched stored digest and audit custody integrity. Require a human-selected decision on whether to recalculate digest inside the final `IMMEDIATE` transaction, how to handle legacy corrupt versions without destructive rewrites, and what constitutes authoritative approval.
- Registered-handler adversarial tests must prove zero writes to library item/version/audit, engagement/requirement/assessment/evidence rows on denial; verify no info disclosure under the chosen DEC-02 threat model and no retroactive changes to exact already-consumed versions.
